# ML Security Pipeline

Двухконтурный пайплайн проверки безопасности ML-моделей и кода-обёртки для CI/CD **Мос.Хаба** с интерактивным центром триажа находок. Работает на стандартной библиотеке Python 3.11+ без обязательной установки внешних пакетов (опционально использует `pip-audit` и `bandit`).

[План проекта и чеклист задач](TASKS.md) · [Журнал и шаблон триажа](docs/triage.md) · [Слайды защиты](docs/defense.pptx)


## Конкурсный профиль Swordfish Security

Конфигурация [Мос.Хаба](.gitlab-ci.yml) запускает два контура. В контуре модели есть одна задача. В контуре обёртки есть независимые задачи для `api`, `cache`, `executor` и `llm`. Каждый сканер восстанавливает только собственный кэш по SHA-256 входов и кода правил. Правки `triage-sfs.json` пересчитывают отчёт и не сбрасывают кэш сканеров.

- [Отчёт триажа на файлах организаторов](docs/sfs-triage.md) и [машиночитаемый отчёт](docs/sfs-report.json)
- [Презентация защиты](docs/sfs-defense.pptx) и [чеклист](TASKS.md)

### Локальное воспроизведение

Разместите распакованный `task_export` в отдельной папке. Команды ниже читают модель и исходники как данные. Запуск сервера из архивного стенда, установка его зависимостей и десериализация для сканирования не требуются.

```sh
export SFS_INPUT_DIR="/absolute/path/to/task_export"
mkdir -p ci-reports
for scope in model api cache executor llm; do
  python3 -m backend.sfs_scan "$scope" --input "$SFS_INPUT_DIR" > "ci-reports/$scope.json"
done
python3 -m backend.sfs_report --reports ci-reports --markdown ci-reports/triage.md > ci-reports/report.json
python3 -m unittest discover -v
```

Чтобы посмотреть результат, запустите `python3 -m backend.app` и выберите **Конкурсный стенд SFS**. Свежий результат можно открыть через **Загрузить report.json**. Карта показывает три статически подтверждённых связи между входами и потенциальными эффектами. Она не запускает проверяемый сервис.

### Настройка раннера Мос.Хаба

1. Добавьте файлы решения в публичный проект команды. Перед публикацией согласуйте формат передачи материалов организаторов. Сами входы передавайте из закрытого каталога, доступного проектному раннеру только на чтение.
2. Зарегистрируйте доверенный раннер с тегом `sfs-local`. Для shell нужен Python 3.12. Для Docker примонтируйте папку с входами read-only в контейнер задачи. Используйте защищённый проектный раннер, без допуска недоверенных веток.
3. Задайте переменную CI `SFS_INPUT_DIR` с путём, видимым раннеру. Без переменной ожидается локальный каталог `task_export` в рабочем каталоге задачи. Включите сохранение кэша на раннере и оставьте раздельный кэш защищённых веток.
4. Сделайте push в Мос.Хаб. Задача `triage` собирает результаты, сохраняет JSON и Markdown даже при ошибке и возвращает код 1, если отчёт отсутствует, проверка неполна или у находки нет решения с обоснованием. Артефакты доступны участникам проекта с ролью Developer и выше. [Документация по доступу к CI-артефактам](https://docs.gitlab.com/ci/yaml/#artifactspublic)
5. Проверьте повторный запуск на том же раннере. После изменения только одного компонента в его логе появится `cache=miss`, у остальных — `cache=hit`. Холодный раннер пересканирует все входы.

Разрешённые статусы в `triage-sfs.json` — `true_positive`, `false_positive`, `accepted_risk`. Ключ решения включает SHA-256 соответствующего файла и доказательство. При изменении файла старый статус не переносится. Успешный этап `triage` означает полноту разбора. Подтверждённые уязвимости остаются задачами исправления.

### Изолированный бонус

В `examples/sfs-bonus/` есть отдельный чат-шаблон с командой вывести **YOU ARE HACKED** и синтетическая ветка обхода авторизации, которая возвращает только строку. Автотест проверяет статическое обнаружение обоих образцов. Вывод реальной модели при инференсе не проверялся.

## Возможности контуров

1. **Контур 1 — Проверка ML-модели (`backend/scanners/model.py`)**:
   * **Статический анализ сериализации без исполнения кода**: дизассемблирование опкодов Pickle (`pickletools.genops`) внутри `.pkl`, `.pt`, `.pth`, `.ckpt`, `.bin`, `.joblib` (включая ZIP-архивы PyTorch и вложенные потоки `torch.storage._load_from_bytes`), проверка `Lambda`-слоёв в `.h5`/`.keras`, инспекция границ буферов `.safetensors`, проверка Path Traversal во внешних тензорах `.onnx` (`CVE-2024-5187`) и хуков `auto_map` в `config.json`.
   * **Статистический детектор закладок (backdoors / trojans) в весах**: прямая распаковка буферов `float32` из `.safetensors`, `.pt`/`.pth`, `.npy`/`.npz` и `.json` без вызова `torch.load()` с расчётом $L_\infty$-нормы, Z-score выбросов, эксцесса (kurtosis), детектом гиперактивных нейронов-триггеров ($L_2$-норма строки слоя) и перекоса смещений (`bias`) целевого класса, а также сверкой SHA-256 с `reference.json`.
   * **Проверка зависимостей (SCA)**: сверка `requirements.txt`, `pyproject.toml`, `environment.yml` со встроенной офлайн-базой CVE (`PyTorch`, `Transformers`, `ONNX`, `Keras`, `TensorFlow`, `Pillow`, `PyYAML`, `MLflow`, `Gradio`, `FastAPI`, `Ray`, `Joblib` и др.) + интеграция с `pip-audit`.
2. **Контур 2 — Статический анализ кода-обёртки (`backend/scanners/wrapper.py`)**:
   * **AST-анализатор Python и SAST-правила**: выявление `torch.load()` без `weights_only=True`, `pickle.load`/`joblib.load`, `yaml.load` без `SafeLoader`, `from_pretrained(..., trust_remote_code=True)`, `eval`/`exec`, `os.system` и `subprocess(..., shell=True)`, SQL-инъекций, SSRF, Path Traversal, `debug=True` и захардкоженных токенов (`hf_`, `sk-`, `AKIA`, приватных ключей).
3. **Сборка отчёта и триаж (`backend/report.py`, `triage.json`, `frontend/`)**:
   * Раздельный учёт статуса работы самого сканера (`ok`, `skipped`, `unsupported_format`, `error`) и статуса триажа каждой находки (`confirmed`, `needs_review`, `false_positive`, `fixed`).
   * Веб-интерфейс с фильтрацией, переключением демо-стендов, редактированием карточек триажа в один клик и экспортом таблицы в формат `docs/triage.md`.

## Быстрый старт и запуск в VS Code

1. Откройте папку `ml-security` через **File → Open Folder**.
2. Подготовьте демонстрационные артефакты (или поместите файлы организаторов в `model/` и `wrapper/`):

   ```sh
   # Заполнить папки model/ и wrapper/ демо-набором с уязвимостями и закладкой в весах:
   python3 -m backend.report --preset vulnerable

   # Либо заполнить чистым эталонным набором (SafeTensors + безопасная обёртка):
   python3 -m backend.report --preset clean

   # Удалить из model/ и wrapper/ скопированные демо-файлы:
   python3 -m backend.report --preset empty
   ```

   Пресеты заменяют только файлы, которые совпадают с демо-образцами. Если в папках есть свои материалы, для просмотра стендов выберите нужный режим в интерфейсе.

3. Запустите локальный сервер интерфейса и API:

   ```sh
   python3 -m backend.app
   ```

   Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). API доступно по адресам `/api/health`, `/api/report`, `/api/triage` и `/api/workspace`. Если порт занят, укажите `--port 8001`.


## Настройка синтетического демо

Для локального демо используйте кнопки выбора стенда. Флаг `--enforce-gate` старого агрегатора `backend.report` демонстрирует политику по серьёзности. Конкурсный CI использует описанный выше `backend.sfs_report` с обязательным триажем.

## Кэш и карта доказательств

У `model-scan` и `wrapper-scan` раздельный кэш исходных результатов. Ключ включает содержимое и пути входов, код соответствующего сканера и версию Python. Неизменившийся контур выдаёт `hit` без повторного запуска анализатора. Триаж и граф пересчитываются на каждом запуске из текущего `triage.json`. Ветка использует отдельный кэш. Для повторного полного сканирования задайте `MLSEC_DISABLE_CACHE=1`. На новом раннере без сохранённого кэша оба контура запускаются с нуля. [Механизм CI-кэша](https://docs.gitlab.com/ci/caching/)

В интерфейсе выберите **Уязвимый пример** или откройте свежий JSON из CI. В **Карте доказательств** можно выбрать пиковый вес, строку тензора или смещение. Для выбранной точки видны координаты, метрики и пороги, статус триажа и связь с CI. Прогноз без выбранной находки показывает оставшиеся блокирующие причины и не меняет отчёт. Полный граф доступен в поле `decision_graph`, а предупреждения о покрытии и ошибках находятся в `warnings`.

Дополнительный ModelScan включается переменной `MLSEC_MODELSCAN=1`. Для Docker-раннера задайте `MLSEC_MODEL_IMAGE` с установленным `modelscan==0.8.8` на совместимом Python. Для shell-раннера разместите CLI в PATH. Онлайн-аудит и Bandit работают без кэша. ModelScan использует кэш только в CI, когда образ задачи закреплён через `@sha256:…` и совпадает с `MLSEC_MODEL_IMAGE`. Так смена образа сбрасывает результат. Для встроенного SAST без автоматически обнаруженного Bandit задайте `MLSEC_BANDIT=0`. [Документация ModelScan](https://github.com/protectai/modelscan)

Файл отчёта и кэш могут содержать детали находок из входных материалов. Для проверки приватной модели ограничьте доступ к проекту и артефактам согласно условиям организаторов. Запускайте сканирование недоверенных файлов в изолированном раннере с лимитами памяти, времени и доступа к сети.

## Локальная проверка кэша

Выполните команды два раза подряд. Первый прогон создаст кэш, второй вернёт `hit` для каждого неизменившегося контура.

```sh
python3 -m backend.scan_ci model --path examples/vulnerable/model > model-report.json
python3 -m backend.scan_ci wrapper --path examples/vulnerable/wrapper > wrapper-report.json
python3 -m backend.report model-report.json wrapper-report.json > report.json
python3 -m unittest discover -v
```

## Архитектура проекта

| Путь | Назначение |
| --- | --- |
| `backend/app.py` | Локальный HTTP-сервер, API отчёта, сохранения триажа и переключения стендов |
| `backend/scanners/model.py` | Контур модели: статический разбор Pickle/SafeTensors/ONNX/Keras, поиск закладок в весах и CVE в зависимостях |
| `backend/scanners/wrapper.py` | Контур статического анализа (AST + Regex + Bandit) кода-обёртки |
| `backend/report.py` | Агрегация отчётов, применение решений из `triage.json`, генератор стендов (`--preset`) и расчёт Policy Gate |
| `frontend/` | Дашборд триажа находок, фильтрации и экспорта Markdown-карточек |
| `docs/triage.md`, `triage.json` | Шаблон карточки находки, заполненный журнал триажа и база решений |
| `tests/test_pipeline.py` | Интеграционные сценарии. Модульные проверки хранятся в `tests/test_evidence.py` |
| `.gitlab-ci.yml` | Конфигурация пайплайна для Мос.Хаба (`scan` → `report`) |

## Ограничения проверок

* Проверку выполняет статический анализатор, отдельной проверяющей нейросети в проекте нет. Положение слоя не ограничивает анализ: для SafeTensors обходятся все тензоры, для PyTorch ZIP — все storage-буферы, для NPY/NPZ — все float32-массивы, для JSON — вложенные числовые тензоры с полным путём параметра.
* В SafeTensors (F16/BF16/F32/F64), float32 NPY/NPZ и подходящих PyTorch-буферах проверяются все значения порциями: `NaN`/`Inf`, экстремумы и моменты распределения. При известной форме и порядке C нормы считаются для всех строк, включая промежуточные слои. Для крупных тензоров только квантили (медиана, MAD, p99 и медиана норм строк) оцениваются по выборке до 100 000 точек по всему тензору; это отражается в отчёте. Полный обход требует больше времени, чем проверка префикса.
* PyTorch ZIP пока трактует подходящие storage-буферы как float32 без восстановления dtype, имён и форм из Pickle, поэтому проверки `bias` и норм строк для него недоступны; отчёт явно сообщает это ограничение. Для полной проверки именованных тензоров используйте SafeTensors. Обычный Pickle разбирается статически, извлечение числовых данных из него эвристическое и ограниченное. Для неизвестных форматов отчёт показывает предупреждение о покрытии. Байтовые маркеры проверяются в пределах первых 64 КиБ тензора.
* Статистический детектор троянов выявляет аномалии распределения весов ($L_\infty$-выбросы, гиперактивные нейроны-триггеры, перекос `bias`) и расхождение SHA-256 с эталоном, но не заменяет динамическое тестирование модели на специфических патчах в рантайме.
