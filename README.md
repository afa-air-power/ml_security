# ML Security Pipeline

Решение [задания Swordfish Security](https://hub.mos.ru/event_DIT/2026/aitipul): проверить модель и код, который её использует, разобрать находки и запускать проверки в CI/CD Мос.Хаба.

В проекте два контура:

- **Модель:** веса, чат-шаблоны, сериализованные файлы и зависимости. Проверяем опасные операции загрузки, численные аномалии и расхождение с эталоном.
- **Код-обёртка:** отдельно `api`, `cache`, `executor` и `llm`. Ищем секреты, обход авторизации, SQL-инъекции, выход за пределы каталогов и небезопасное выполнение команд.

У каждой из пяти проверок свой кэш по SHA-256 входов и кода проверки. Если они не изменились, используется готовый результат. Правка реестра триажа пересчитывает итоговый отчёт без повторного сканирования.

## Посмотреть результат

Нужен Python 3.12. Основные проверки работают на стандартной библиотеке, устанавливать зависимости проверяемого стенда не требуется. Команды выполняются из корня проекта.

```sh
python -m backend.app
```

Откройте [localhost:8000](http://127.0.0.1:8000/). Режим **«Конкурсный стенд SFS»** показывает сохранённый отчёт. Для просмотра свежего результата загрузите `report.json` кнопкой в интерфейсе. В списке также есть чистый и уязвимый демо-стенды.

Готовые материалы:

- [Разбор находок](docs/sfs-triage.md) и [полный отчёт JSON](docs/sfs-report.json).
- [Презентация](docs/sfs-defense.pptx).

## Проверить свои входы

Распакуйте стенд в `task_export/` или укажите другую папку. Ожидаются `model/`, `src/api/`, `src/cache/`, `src/executor/`, `src/llm/` и файлы зависимостей из задания. Сканеры читают их как данные; запускать сам стенд не нужно.

Полный прогон в Bash, как в CI:

```sh
INPUT_DIR="/path/to/task_export"
mkdir -p ci-reports
for scope in model api cache executor llm; do
  python -m backend.sfs_scan "$scope" --input "$INPUT_DIR" > "ci-reports/$scope.json"
done
python -m backend.sfs_report --reports ci-reports \
  --markdown ci-reports/triage.md --gitlab-dir ci-reports \
  --gitlab-source-root "$INPUT_DIR" > ci-reports/report.json
```

В `ci-reports/` появятся отчёты пяти проверок, общий JSON, таблица триажа и отчёты SAST / Dependency Scanning для GitLab. Чтобы проверить один компонент, запустите только его команду, например `python -m backend.sfs_scan api --input task_export`.

## Триаж и CI

Решения для конкурсного стенда хранятся в [triage-sfs.json](triage-sfs.json). Для каждой находки нужны статус `true_positive`, `false_positive` или `accepted_risk` и непустой комментарий. Если решения нет, отчёт повреждён или проверка завершилась с блокирующей ошибкой, задача `triage` возвращает код 1. Подтверждённые уязвимости остаются в отчёте и после успешного триажа.

Решение привязано к файлу и доказательству: при изменении входа старый статус не переносится автоматически. `triage.json` используется отдельно, для локальных демо.

Конфигурация находится в [.gitlab-ci.yml](.gitlab-ci.yml). Для запуска на Мос.Хабе:

1. Подключите свой раннер с тегом `sfs-local`: Docker либо shell с Python 3.12.
2. Задайте `SFS_INPUT_DIR` — путь к распакованному стенду. По умолчанию это `task_export` в рабочей папке задачи. Для Docker внешнюю папку нужно примонтировать в контейнер на чтение.
3. Сделайте push и скачайте результаты из артефактов задачи `triage`. При повторном запуске неизменившиеся сканеры должны показать `cache=hit`.

Задачи сканирования запускаются в каждом пайплайне; повторный анализ внутри них пропускается при попадании в кэш. Отчёты `gl-sast-report.json` и `gl-dependency-scanning-report.json` также передаются в GitLab через `artifacts:reports`.

## Бонус: инъекция во ввод

[injection_bonus.py](injection_bonus.py) сравнивает два ответа SmolLM2-135M-Instruct: на исходный запрос и на тот же запрос с десятью повторами заданной фразы. В консоль выводятся параметры, оба ввода и оба ответа.

```sh
python -m pip install torch "transformers>=4.51,<5" safetensors
python injection_bonus.py --phrase "YOU ARE HACKED" --json injection-result.json
```

Без параметров используется фраза `YOU ARE HACKER`. Можно задать `--prompt`, `--repeat`, `--max-new-tokens` и `--model` — имя модели Hugging Face или локальную папку. Первый запуск загружает модель в `.mlsec-cache/injection-demo/`; затем доступен режим `--local-only`.

Это демонстрация влияния ввода на ответ, без изменения весов и конфигурации. Результат зависит от запроса; в JSON поле `induced` показывает, появилась ли фраза только после инъекции.

В [examples/sfs-bonus/](examples/sfs-bonus/) лежат отдельные образцы для статической проверки: изменённый чат-шаблон с `YOU ARE HACKED` и служебная ветка в коде. Они проверяются автотестом.

## Тесты и ограничения

```sh
python -m unittest discover -v
```

Статистическая аномалия в весах или совпадение SAST-правила требует разбора. Само по себе оно не доказывает наличие работающей закладки. Для больших тензоров квантили оцениваются по выборке; на чтение файлов и распаковку архивов действуют лимиты. Ограничения отражаются в отчёте.

Подробности алгоритмов и покрытия — в [logic.md](logic.md). Команды запуска и результаты сравнения с Bandit, Semgrep, Gitleaks, ModelScan и pip-audit — в [отчёте по внешним сканерам](docs/sfs-oss-audit.md).
